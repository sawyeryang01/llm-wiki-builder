# 个人知识库（LLM Wiki）

基于 Andrej Karpathy 的「LLM Wiki」构想搭建：**你负责找资料和提问，AI 负责写页面、建交叉引用、记账。**

这个目录本身就是知识库，也是一个 Obsidian vault。

---

## 快速开始

```bash
# 1. 用 Obsidian 打开这个文件夹（打开文件夹作为仓库）
#    路径：<知识库根目录>

# 2. 把 AGENTS.md 交给你的 Agent，让它先复述规则
#    工作目录设为知识库根目录

# 3. 丢一篇资料进 raw/素材/，然后说：
#    "raw/素材/ 里有一篇新资料，按 AGENTS.md 执行摄取"
```

**第 2 步别省。** 让它复述一遍，你能立刻发现它对规则的理解偏差——等它写了一堆页面再纠正，返工成本高得多。可直接复制的指令见 `操作指令.md`。

## 目录结构

```
├── AGENTS.md          【核心】给 AI 的行为说明书（Schema）
├── CLAUDE.md          AGENTS.md 的副本，供 Claude Code 读取
├── QWEN.md            AGENTS.md 的副本，供 Qwen Code 读取
├── README.md          本文件
├── 方法论.md           方法论详解：原理、国内改造、工具选型、九个坑
├── 操作指令.md          可复制指令库 + 各 Agent 工具接法 + 排错
│
├── index.md           内容索引（AI 每次操作后更新）
├── log.md             操作日志（只追加）
│
├── templates/         页面模板，供 Obsidian 插入
├── raw/               你的资料池（AI 只读）
│   ├── 素材/          文章、报告、PDF 转出的 md
│   ├── 图片/          截图、图表、扫描页
│   ├── 归档/          已处理完的原始资料
│   └── 私有/          ⚠️ 敏感资料，只允许本地模型处理
└── wiki/              AI 维护的知识（你只读）
    ├── 综述.md
    ├── 待建概念.md
    ├── 来源/          每篇资料一篇摘要
    ├── 实体/          人 / 公司 / 产品 / 机构 / 标准 / 项目
    ├── 概念/          原理 / 方法 / 术语 / 技术路线
    └── 对比/          跨来源综合：方案对比、路线选型、立场分歧
```

**读写权限严格分离**：`raw/` 只有你能写，保证事实来源不被篡改；`wiki/` 只有 AI 写，保证你不会手改坏它维护的一致性。

## 日常节奏

| 频率 | 动作 |
|---|---|
| **随时** | 看到好文章 → 剪藏进 `raw/素材/`（先别管它） |
| **每天 15 分钟** | 摄取 1–2 篇。读 AI 的摘要，检查它更新了哪些页面，引导它该强调什么 |
| **每周 30 分钟** | 翻 `index.md` 和 `log.md`；在 Obsidian 图谱视图里逛一圈 |
| **每月** | 跑一次 Lint（指令见 `操作指令.md`） |
| **每季度** | 和 AI 一起修订 `wiki/综述.md`，回头改 `AGENTS.md` |

**最关键的动作**：每次摄取后在图谱视图里确认——新页面和已有页面**有连线**吗？

如果新页面是孤立的，这次摄取就是失败的：资料只是被存下来了，没有被整合进知识结构。这是这套方法和"另一个收藏夹"的唯一区别。

## 资料怎么进来

| 类型 | 怎么处理 |
|---|---|
| 网页文章 | Obsidian Web Clipper 剪藏成 md → `raw/素材/` |
| 微信公众号 | 微信读书导出 / 转 RSS 后剪藏 / 手动复制正文存 md |
| **PDF、扫描件** | **先用 MinerU 转成 md 再存** → `raw/素材/`（不要把 PDF 直接丢给 AI） |
| Word / PPT / Excel | 同上，MinerU 也支持 |
| 视频 / 播客 | 转文字稿存 md，原始链接写文件开头 |
| 图片 / 截图 | 剪藏后按 `Ctrl+Shift+D` 下载到 `raw/图片/` |

## 隐私分层（重要）

`raw/私有/` 用于存放**客户名称、报价、投标文件、内部文档**等敏感资料。

**这个目录下的内容禁止发送到任何云端大模型。**

- 处理私有资料前，先确认 Agent 用的是**本地模型端点**（Ollama / vLLM 跑 Qwen、DeepSeek、GLM 开源版）
- 确需云端分析时先脱敏：客户名换代号、删掉报价数字和联系方式
- 该目录已写入 `.gitignore`，不会同步到任何远端
- 来自私有资料的 wiki 页面，frontmatter 的 `tags` 里要带 `私有`

完整规则见 `AGENTS.md` 第 7 节红线第 5 条。简言之：**敏感资料只在本地模型上处理，云端 Agent 一律只拿到脱敏后的版本。**

## Obsidian 配置（已预置）

`.obsidian/` 里有预置配置，首次打开应该已经生效：

- 附件默认位置 → `raw/图片/`
- 新建笔记默认位置 → `raw/素材/`
- 使用 `[[wikilink]]` 语法（与 AGENTS.md 的约定一致）
- 排除 `.workbuddy/`、`outputs/`、`.git/`，图谱里不会出现这些噪音

**需要手动确认的两项**：

1. **设置 → 文件与链接 → 附件默认位置** 应为 `raw/图片`
2. **设置 → 快捷键** 搜 `Download`，给「下载当前文件的附件」绑一个快捷键（建议 `Ctrl+Shift+D`）

**想装的话推荐两个社区插件**：

- `Dataview` — 让 AI 写在 frontmatter 里的 `type` / `tags` / `updated` 变成动态表格
- `Marp` — 让 AI 直接把 wiki 内容渲染成幻灯片
