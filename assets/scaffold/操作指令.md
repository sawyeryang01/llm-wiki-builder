# 操作指令手册

配套 `方法论.md` 使用。这一份是纯操作层：**怎么把 Agent 接到这个库上，以及日常说什么。**

可直接复制的指令在第三节。指令里不需要重复规则——规则都在 `AGENTS.md` 里，Agent 每次会先读它。

---

## 一、Agent 读哪个 schema 文件

| 工具 | 默认读取的文件名 |
|---|---|
| OpenAI Codex 系 | `AGENTS.md` |
| Claude Code | `CLAUDE.md` |
| Qwen Code | `QWEN.md` |
| Cursor / Cline / Roo Code | 各自的自定义规则文件，或手动在对话里贴 |

本库已经以 `AGENTS.md` 为唯一真源，并生成了 `CLAUDE.md`、`QWEN.md` 两份副本。

> **改 `AGENTS.md` 之后记得同步这两个副本**：
> ```bash
> cd <知识库根目录>
> cp AGENTS.md CLAUDE.md && cp AGENTS.md QWEN.md
> ```

## 二、把 Agent 接到库里

### 通用要求

Agent 的**工作目录必须是知识库根目录**，即 `<知识库根目录>`。否则它会看到一堆无关文件，把上下文浪费掉。

### Qwen Code（阿里开源，国内直连）

```bash
# 安装（需要 Node.js 22+）
npm install -g @qwen-code/qwen-code@latest

# 进入知识库目录
cd <知识库根目录>
qwen

# 首次运行选认证方式
/auth
```

模型配置写在 `~/.qwen/settings.json`。支持三种接法：

- 阿里云百炼 Coding Plan / API Key（国内直连）
- 第三方兼容端点（智谱、Kimi、DeepSeek、MiniMax 等在 `/auth` 列表里可选）
- **本地 Ollama / vLLM** —— 处理 `raw/私有/` 时切这个

```json
{
  "modelProviders": {
    "openai": [
      {
        "id": "qwen3-coder",
        "name": "qwen3-coder",
        "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1",
        "envKey": "DASHSCOPE_API_KEY"
      }
    ]
  },
  "env": { "DASHSCOPE_API_KEY": "sk-xxxxxxxx" },
  "model": { "name": "qwen3-coder" }
}
```

### Claude Code（配国产兼容端点）

Claude Code 本体免费，只需要一个兼容 Anthropic 协议的端点。智谱 GLM Coding Plan、火山方舟等都原生支持。

按各家文档设置 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN` 环境变量，然后：

```bash
cd <知识库根目录>
claude
```

### 当前对话工具（WorkBuddy 等）

不需要装任何东西。工作目录指到 `<知识库根目录>`，让它先读 `AGENTS.md`，然后按第三节的指令开工。

### 其他工具

OpenCode、Cline、Roo Code、Trae、CodeBuddy 都可以。**唯一的硬要求是能读写本地文件。** 纯网页版对话框不行——它看不到你的 `raw/` 目录。

## 三、指令库

### 1. 首次接入（**必做，别跳**）

```
请完整阅读 AGENTS.md，然后回答：
1. 这个知识库的目录结构和读写权限规则是什么？
2. 你执行"摄取"时的完整步骤有哪几步？
3. 你对 raw/ 目录有哪些操作限制？
4. 建一个"概念页"的门槛是什么？
5. 哪些文件不参与 Lint 统计？

读完先复述，不要动手，我确认后再开始。
```

**为什么要让它复述**：你能立刻发现它对规则的理解偏差。等它已经写了一堆页面再纠正，返工成本高得多。

### 2. 摄取（日常主力）

```
raw/素材/ 里有新资料《XXX》。按 AGENTS.md 执行摄取。

要求：
- 先读一遍，跟我聊聊你判断的重点，以及可能和现有知识产生的关联
- 检查是否与已有来源冲突。如有冲突，建对比页并列呈现，不要替我下结论
- 完成后按 AGENTS.md 规定的格式汇报：触碰了哪些页面 / 发现了什么矛盾 / 建议新建什么对比页
```

### 3. 查询（带"落页"要求）

```
基于 wiki 回答：XXX？

要求：
1. 每个结论标注来源页面
2. wiki 里信息不足就明确说"不足"，不要用通用知识补齐 —— 我需要知道我的知识库哪里有洞
3. 如果这次回答产生了新的综合分析或对比，把它归档成 wiki/对比/ 下的新页面
```

**第 3 条是整个方法的分水岭。** 参考 Karpathy 原话：

> Good answers can be filed back into the wiki as new pages. A comparison you asked for, an analysis, a connection you discovered — these are valuable and shouldn't disappear into chat history.

### 4. 体检（每摄取 10 篇做一次）

```
对 wiki 执行 Lint。

分两类处理：
- 可自动修复的（缺反链、index.md 不同步、空链接现在可以补上了、孤立图片）：
  直接修，然后告诉我改了什么
- 需要判断的（页面间矛盾、被推翻但未标注的旧结论、confidence 低的页面）：
  只列清单，等我确认，不许擅自改

注意：README.md、方法论.md、操作指令.md、templates/、raw/ 都不参与统计，
不要把它们报告为孤儿页面。

最后给三条建议：下一步补什么资料、展开哪个对比、验证哪个结论。
```

### 5. 批量摄取（谨慎）

```
raw/素材/ 下有 8 篇资料，批量摄取。

先给我一份处理清单：每篇要建哪些页面、更新哪些页面。
我确认后再执行。矛盾之处单独汇总，不要自行裁决。
```

### 6. 让 AI 自己造工具（可选的进阶）

```
wiki/ 已经超过 200 个页面，index.md 定位效率开始下降。
请写一个本地 markdown 检索脚本，要求：
- 支持中文分词
- BM25 + 简易向量混合排序
- 提供 CLI 接口，方便你直接调用
用 Python 写，放在 scripts/ 下，不要动 wiki/ 和 raw/。
```

Karpathy 提到社区里有人用 `qmd`（本地 markdown 混合检索 + LLM 重排，带 MCP 接口）。但这个需求**到几百个页面以上才出现**，别提前优化。

### 7. 切换本地模型处理敏感资料

```
接下来只处理 raw/私有/ 下的资料。请确认你当前用的是本地模型端点。
如果不是，停下来告诉我，我切完再继续。
这批资料全程不得发送到任何云端接口。
```

### 8. 修订 schema

```
我打算改 AGENTS.md 里的一条规则：（说明改什么、为什么）。
先告诉我这个改动会影响哪些现有页面，有没有需要连带调整的地方，
我确认后你再改，并同步 CLAUDE.md 和 QWEN.md 两份副本。
```

## 四、Windows + 中文路径排错

中文文件名在 Obsidian 里体验最好，但在某些命令行工具链里可能出现编码问题。症状是 Agent 说"找不到文件"或写出的文件名乱码。

**判断方法**：让 Agent 执行 `ls raw/素材/`，看它读出来的文件名和实际是否一致。

**如果乱码**，改用英文 slug 方案：

```
wiki/来源/urban-lifeline-policy.md     ← 文件名用英文
---
type: 来源
title: 城市生命线安全工程政策梳理        ← 中文标题写在这里
---
# 城市生命线安全工程政策梳理            ← H1 也写中文
```

Obsidian 会优先显示 frontmatter 里的 `title`（配 `Front Matter Title` 插件）或 H1，阅读体验几乎不受影响，但工具链兼容性好很多。

**统一原则：整个库二选一，不要混用**，否则 `[[链接]]` 会对不上。

## 五、日常节奏

| 频率 | 动作 |
|---|---|
| **随时** | 看到好文章 → 剪藏进 `raw/素材/`（先别管它） |
| **每天 15 分钟** | 摄取 1–2 篇。读 AI 的摘要，检查它更新了哪些页面，引导它该强调什么 |
| **每周 30 分钟** | 翻 `index.md` 和 `log.md`，看看这周知识的形状变了没有；在图谱里逛一圈 |
| **每月** | 跑一次 Lint |
| **每季度** | 读 `wiki/综述.md`，和 AI 一起修订整体判断；回头改 `AGENTS.md` |

**最关键的动作**：每次摄取后在图谱视图里确认——新页面和已有页面**有连线**吗？

如果新页面是孤立的，这次摄取就是失败的：资料只是被存下来了，没有被整合进知识结构。这也是这套方法和"另一个收藏夹"的唯一区别。

## 六、Obsidian 快捷键建议

| 动作 | 建议键位 |
|---|---|
| 下载当前文件的附件（存图到 `raw/图片/`） | `Ctrl+Shift+D` |
| 插入模板（从 `templates/`） | 用命令面板 `Ctrl+P` → Insert template |
| 打开图谱视图 | 命令面板 → Open graph view |
| 全局搜索 | `Ctrl+Shift+F` |

模板里的日期用了 `"{{date:YYYY-MM-DD}}"` 占位符，**必须带引号**——不带引号时 frontmatter 不是合法 YAML（`{` 开头会被解析成 flow mapping），Obsidian 会在这些文件上报属性解析错误。

占位符靠 **核心插件 Templates** 插入时才会替换成真日期。若插入后日期没变，去 **设置 → 核心插件** 确认 Templates 已启用。替换后值是带引号的字符串（如 `created: "2026-10-01"`），Obsidian 属性面板里可能显示为文本而非日期类型——不影响使用，Agent 照常读写。
